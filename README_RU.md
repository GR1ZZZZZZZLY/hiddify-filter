# Безопасный фильтр подписок HAPP/Hiddify v4

GitHub Actions приблизительно каждые 15 минут загружает публичный список
`verified`, удаляет узлы с российской меткой, убирает дубликаты, проверяет
структуру VLESS/REALITY-ссылок и публикует три подписки.

- `reality_tcp.txt` — основной и наиболее строгий профиль:
  `VLESS + TCP/RAW + REALITY + XTLS Vision`;
- `reality_all.txt` — расширенный безопасный REALITY-профиль:
  TCP/RAW, XHTTP, SplitHTTP и gRPC;
- `subscription.txt` — резерв со всеми протоколами без RU. Он не проходит
  строгую проверку REALITY и не рекомендуется для важных действий;
- `security_report.json` — обезличенный отчёт: сколько записей принято и по
  каким причинам остальные отброшены. Ключей и адресов узлов в отчёте нет.

Исходник:

`https://raw.githubusercontent.com/0xRadikal/Free-v2ray-Configs/main/verified/configs.txt`

## Что изменилось в v4

Перед попаданием в два REALITY-профиля ссылка должна пройти все проверки:

- корректная схема `vless://`, UUID, публичный адрес и порт;
- `security=reality` и явный `encryption=none`;
- допустимый транспорт;
- корректный 32-байтовый ключ REALITY;
- корректные `SNI/serverName`, fingerprint и shortId;
- отсутствие конфликтующих значений критичных параметров;
- отсутствие управляющих символов и аномально длинных полей;
- отсутствие небезопасных флагов `allowInsecure`, `skip-cert-verify` и аналогов;
- для строгого профиля дополнительно обязателен XTLS Vision.

Проверки выполняются локальными unit-тестами перед каждой публикацией. Если
тесты не пройдут, старые рабочие файлы останутся в репозитории.

Важно: проверка подтверждает только корректность конфигурации. Она не может
доказать честность владельца публичного сервера, отсутствие журналирования или
правильность геометки.

## Как обновить существующий репозиторий

1. Распакуйте архив.
2. В GitHub откройте свой репозиторий и выберите
   `Code → Add file → Upload files`.
3. Перетащите в окно четыре элемента из архива, сохранив пути:

   - `filter_subscription.py`;
   - `test_filter_subscription.py`;
   - `README_RU.md`;
   - `.github/workflows/update.yml`.

4. GitHub покажет предупреждение, что одноимённые файлы будут заменены. Нажмите
   `Commit changes` и подтвердите коммит в ветку `main`.
5. Если каталог `.github` не загрузился, откройте существующий файл
   `.github/workflows/update.yml`, нажмите карандаш, замените его содержимое
   текстом из файла архива и сделайте отдельный коммит.
6. Откройте `Actions → Update filtered HAPP subscriptions → Run workflow`.
7. Успешный запуск должен содержать зелёные шаги:

   - `Run offline safety tests`;
   - `Build safer subscriptions without RU nodes`;
   - `Commit changed subscription`.

8. В корне репозитория появится `security_report.json`, а существующие
   подписки будут обновлены.

URL подписок не изменяются, поэтому удалять и добавлять их в HAPP заново не
нужно:

`https://raw.githubusercontent.com/ВАШ_ЛОГИН/hiddify-filter/main/reality_tcp.txt`

`https://raw.githubusercontent.com/ВАШ_ЛОГИН/hiddify-filter/main/reality_all.txt`

`https://raw.githubusercontent.com/ВАШ_ЛОГИН/hiddify-filter/main/subscription.txt`

После успешного workflow вручную обновите подписки в HAPP и заново запустите
`via Proxy — GET`.

## Настройка HAPP/Hiddify

Рекомендуемые названия:

- `REALITY TCP SAFE без RU` — основной профиль;
- `REALITY SAFE расширенный без RU` — запасной;
- `VERIFIED резерв без RU` — только для ручного поиска альтернативы.

GitHub формирует файлы каждые 15 минут. Заголовок подписки предлагает клиенту
обновление раз в час; фактический интервал также зависит от настройки HAPP.

Рекомендуемая проверка: `via Proxy — GET` с URL
`https://cp.cloudflare.com/generate_204`.

## Публичный или приватный репозиторий

Для простой Raw-ссылки в HAPP репозиторий должен быть публичным. Приватный
репозиторий требует авторизации GitHub, которую обычное поле подписки HAPP не
передаёт. В этот репозиторий нельзя добавлять личные, платные или самостоятельно
созданные VPN-ключи.

## Ограничения безопасности

- Владелец активного узла видит ваш реальный IP, время, объём трафика и адреса
  назначений; HTTPS по-прежнему защищает содержимое при действительном
  сертификате.
- Наличие пинга или успешного GET не подтверждает отсутствие журналирования.
- Страна определяется по метке исходного проекта, а не независимой GeoIP-
  проверкой.
- Публичные узлы разумно использовать для обычных сайтов, но не для банка,
  криптокошельков, Госуслуг, рабочих административных систем и смены важных
  паролей.
- Никогда не принимайте предупреждения о сертификатах и не устанавливайте
  сертификаты или приложения, предложенные владельцем узла.

Если источник недоступен, тесты не проходят или после фильтра осталось слишком
мало записей, workflow завершится ошибкой и не перезапишет последние рабочие
подписки.
