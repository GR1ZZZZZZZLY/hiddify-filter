# Фильтр подписок HAPP/Hiddify v6.1

v6.1 объединяет два независимо поддерживаемых источника с upstream-проверкой
подключения, удаляет RU-узлы, строго проверяет REALITY-параметры, объединяет
дубликаты и каждые 15 минут пересчитывает рейтинг и историю доступности. При
наличии свежего локального отчёта узлы, реально работающие через сеть
пользователя, получают максимальный приоритет и отдельную подписку.

## Источники

Публикуемые кандидаты берутся из:

- `0xRadikal/Free-v2ray-Configs — verified/configs.txt`;
- `Danialsamadi/v2go — AllConfigsSub.txt`.

Если одна конфигурация встречается в обоих источниках под разными названиями,
она публикуется один раз и получает бонус за перекрёстное подтверждение. URI из
0xRadikal имеет приоритет только как отображаемое имя. Списки `fast`, `secure`
и `top100` 0xRadikal служат дополнительными сигналами рейтинга и сами по себе
новых конфигураций не публикуют.

## Готовые подписки

- `reality_best.txt` — до 50 лучших текущих строгих REALITY-узлов;
- `reality_stable.txt` — до 100 узлов, появившихся минимум в 6 из последних
  8 запусков (окно около 2 часов);
- `reality_durable.txt` — до 50 узлов, появившихся минимум в 72 из последних
  96 запусков (окно около 24 часов) и подтверждённых обоими источниками;
- `reality_local.txt` — до 50 текущих строгих узлов, прошедших минимум 2 из 3
  настоящих GET-проверок через Xray с компьютера пользователя;
- `reality_tcp.txt` — полный строгий список
  `VLESS + TCP/RAW + REALITY + XTLS Vision`;
- `reality_all.txt` — расширенный безопасный REALITY-список, включая XHTTP,
  SplitHTTP и gRPC;
- `subscription.txt` — все протоколы без RU, нестрогий аварийный резерв;
- `security_report.json` — обезличенная статистика;
- `node_history.json` — SHA-256-идентификаторы и счётчики присутствия;
- `checksums.sha256` — контрольные суммы семи подписок.

`DURABLE` в первые сутки закономерно будет пустым: код не выдаёт короткое
наблюдение за полноценную 24-часовую стабильность.

## Что изменилось относительно v6

- добавлена необязательная локальная проверка через сеть пользователя;
- локально подтверждённые узлы получают наивысший вес в `BEST`;
- появился отдельный профиль `LOCAL` с правилом 2/3;
- локальные результаты старше трёх часов автоматически игнорируются;
- отсутствие, просрочка или повреждение локального отчёта не останавливают
  обновление обычных профилей;
- HMAC-секрет поступает только из GitHub Actions Secret и не записывается в
  подписки, отчёт, историю или контрольные суммы.

История не содержит URI, IP-адресов, UUID, SNI или ключей. Исчезнувший URI из
истории восстановить нельзя, поэтому отсутствующий узел никогда не публикуется.

## Установка поверх v6

1. Распакуйте архив.
2. В GitHub откройте репозиторий `hiddify-filter`.
3. Через `Code → Add file → Upload files` загрузите с заменой:

   - `filter_subscription.py`;
   - `test_filter_subscription.py`;
   - `README_RU.md`.

4. Файл `.github/workflows/update.yml` замените отдельно: откройте текущий
   workflow, нажмите карандаш, вставьте содержимое файла из архива и сделайте
   коммит в `main`.
5. **Не удаляйте `node_history.json`**: v6.1 продолжит существующую историю.
6. Настройте локальный отчёт по инструкции ниже.
7. Откройте `Actions → Update filtered HAPP subscriptions → Run workflow`.
8. Дождитесь зелёного результата. Прежние подписки обновятся по тем же URL, а в
   корне появится `reality_local.txt`.

Существующие профили HAPP перенастраивать не нужно: имена и Raw-URL старых
файлов сохранены.

## Подключение локального отчёта

1. Завершите три полных запуска Windows-тестера с отключённым HAPP/VPN.
2. Запустите `03-COPY-SECRET.cmd`. Секрет будет помещён в буфер обмена.
3. В репозитории GitHub откройте `Settings → Secrets and variables → Actions`
   и создайте repository secret:

   - имя: `LOCAL_TEST_HMAC_KEY`;
   - значение: содержимое буфера обмена.

4. Загрузите в корень репозитория файл `data\local_results.json` из папки
   тестера под именем `local_results.json`.
5. Не загружайте `local_test_key.dpapi`, `local_history.json`, временные
   конфигурации или содержимое буфера обмена.
6. Запустите workflow не позднее трёх часов после локального теста.

В публичном `local_results.json` находятся время и агрегаты проверки,
задержки, счётчики и непрозрачные HMAC-идентификаторы. URI, IP, UUID, SNI,
REALITY-ключ и HMAC-секрет туда не записываются. Обычный SHA-256 здесь не
используется: публичные URI можно было бы перебрать, а HMAC без секрета
сопоставить нельзя.

Для последующих ручных обновлений достаточно снова выполнить полный локальный
тест и заменить в репозитории только `local_results.json`. Секрет повторно
создавать или менять не нужно.

## Как читать отчёт

В `security_report.json` особенно полезны:

- `merge.cross_source_identities` — сколько подключений найдено в обоих
  публикующих источниках;
- `history.stable_candidates` — сколько узлов прошло правило 6/8;
- `history.durable_candidates` — сколько узлов прошло правило 72/96 и
  cross-source проверку;
- `history.window_complete_current` — сколько текущих узлов накопило полное
  окно 96 запусков;
- `outputs.*` — фактическое количество строк в каждом профиле;
- `diversity.*.skipped_*` — сколько кандидатов отброшено лимитами концентрации.

Раздел `local`:

- `status: active` — отчёт свежий, а HMAC-секрет имеет корректный формат;
- `status: stale` — отчёт старше трёх часов и игнорируется;
- `status: secret_missing` — файл есть, но secret не настроен;
- `status: results_missing` — secret есть, но файла нет;
- `status: invalid` — отчёт или secret не прошёл строгую проверку;
- `qualified_report_nodes` — узлы с результатом не ниже 2/3;
- `matched_current_strict` — сколько записей найдено в текущем строгом списке;
- `selected` — фактический размер `reality_local.txt`.

## Публичность и безопасность

Для обычной Raw-ссылки HAPP репозиторий должен быть публичным: приватный Raw
требует GitHub-авторизацию, которую поле подписки HAPP не передаёт. Не помещайте
в этот репозиторий личные или платные ключи.

Upstream HTTP-проверка, локальный GET-тест, синтаксическая валидация, история и
совпадение источников не устанавливают личность владельца узла. Публичный
сервер видит ваш IP, время, объём соединений и адреса назначения. Не используйте
публичные узлы для банка, криптокошельков, Госуслуг, рабочих админ-систем и
смены важных паролей; не принимайте предупреждения браузера о сертификатах.

Если тесты не проходят, один из источников недоступен или строгих записей
осталось меньше безопасного минимума, workflow завершается ошибкой и не
заменяет последнюю успешную публикацию.
