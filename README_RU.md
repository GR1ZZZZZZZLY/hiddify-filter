# Фильтр подписок HAPP/Hiddify v5

GitHub Actions каждые 15 минут строит безопаснее отфильтрованные подписки без
узлов с российской меткой. Версия v5 сохраняет все прежние URL и добавляет два
компактных профиля с ранжированием, историей стабильности и ограничением
концентрации узлов у одного адреса, подсети или страны.

## Какие файлы публикуются

- `reality_best.txt` — до 50 лучших строгих REALITY-узлов. Основной профиль
  для HAPP: приоритет получают узлы, одновременно присутствующие в upstream-
  списках `top100`, `secure` и `fast`;
- `reality_stable.txt` — до 100 строгих узлов, подтверждённых как минимум двумя
  последовательными запусками. Это более широкий запасной профиль;
- `reality_tcp.txt` — полный строгий список
  `VLESS + TCP/RAW + REALITY + XTLS Vision`;
- `reality_all.txt` — полный расширенный безопасный REALITY-список: TCP/RAW,
  XHTTP, SplitHTTP и gRPC;
- `subscription.txt` — все протоколы без RU. Это нестрогий аварийный резерв;
- `security_report.json` — обезличенная статистика фильтрации и ранжирования;
- `node_history.json` — только SHA-256-хэши идентификаторов и счётчики. URI,
  IP-адреса, UUID и ключи в истории не сохраняются;
- `checksums.sha256` — контрольные суммы пяти файлов подписок.

## Откуда берутся узлы

Единственный источник публикуемых конфигураций:

`https://raw.githubusercontent.com/0xRadikal/Free-v2ray-Configs/main/verified/configs.txt`

Списки `fast`, `secure` и `top100` используются только для присвоения рейтинга
уже найденным в `verified` узлам. Узел из дополнительного списка не может сам по
себе попасть в наши подписки.

## Как работает стабильность

1. Новый строгий узел появляется в `reality_best.txt` сразу, если имеет хороший
   рейтинг.
2. После двух последовательных запусков он получает статус `trusted` и может
   попасть в `reality_stable.txt`.
3. Если подтверждённый узел исчез, его хэш остаётся в карантине до восьми
   запусков. Сам URI не хранится и в подписку во время отсутствия не попадает.
4. Если узел вернулся до окончания карантина, его доверенный статус
   восстанавливается сразу.
5. При самом первом запуске `reality_stable.txt` временно заполняется лучшими
   текущими узлами, чтобы новая подписка не была пустой. Уже следующий запуск
   примерно через 15 минут подтвердит повторно присутствующие узлы.

Ранжирование и история уменьшают количество бесполезных `n/a`, но не могут
гарантировать, что публичный узел останется доступен между обновлением GitHub и
проверкой HAPP.

## Ограничение концентрации

Компактные профили стараются не зависеть от одной точки отказа:

- `BEST`: не более 12 узлов с одной меткой страны, 2 на один endpoint и 3 из
  одной IPv4 `/24` или IPv6 `/48` подсети;
- `STABLE`: не более 30 на страну, 3 на endpoint и 5 на подсеть.

Страна берётся из метки исходного проекта и не является независимой GeoIP-
проверкой.

## Переход с v4 на v5

1. Распакуйте архив v5.
2. В своём репозитории GitHub откройте `Code → Add file → Upload files`.
3. Перетащите содержимое распакованной папки, сохранив пути:

   - `filter_subscription.py`;
   - `test_filter_subscription.py`;
   - `README_RU.md`;
   - `.github/workflows/update.yml`.

4. GitHub отметит три обычных файла как заменяемые. Нажмите `Commit changes` и
   подтвердите коммит в `main`.
5. Если скрытая папка `.github` не загрузилась, откройте существующий файл
   `.github/workflows/update.yml`, нажмите карандаш, замените его содержимое
   текстом из архива и сделайте отдельный коммит.
6. Откройте `Actions → Update filtered HAPP subscriptions → Run workflow`.
7. После первой зелёной сборки в корне появятся новые файлы
   `reality_best.txt`, `reality_stable.txt`, `node_history.json` и
   `checksums.sha256`. Прежние три подписки также обновятся.
8. Подождите следующего планового запуска или запустите workflow второй раз —
   так история подтвердит узлы, присутствующие два запуска подряд.

Удалять старые профили HAPP не требуется: эти URL сохранены:

`https://raw.githubusercontent.com/ВАШ_ЛОГИН/hiddify-filter/main/reality_tcp.txt`

`https://raw.githubusercontent.com/ВАШ_ЛОГИН/hiddify-filter/main/reality_all.txt`

`https://raw.githubusercontent.com/ВАШ_ЛОГИН/hiddify-filter/main/subscription.txt`

## Новые подписки для HAPP

Добавьте в HAPP две Raw-ссылки:

`https://raw.githubusercontent.com/ВАШ_ЛОГИН/hiddify-filter/main/reality_best.txt`

Название: `REALITY BEST без RU`

`https://raw.githubusercontent.com/ВАШ_ЛОГИН/hiddify-filter/main/reality_stable.txt`

Название: `REALITY STABLE без RU`

Рекомендуемый порядок использования:

1. `REALITY BEST без RU` — основной;
2. `REALITY STABLE без RU` — запасной;
3. `REALITY TCP SAFE без RU` — ручной поиск альтернатив;
4. расширенный и общий резерв — только если строгие профили не помогли.

В HAPP используйте `via Proxy — GET` и тестовый URL:

`https://cp.cloudflare.com/generate_204`

GitHub формирует файлы каждые 15 минут. Заголовок файлов предлагает HAPP
обновляться раз в час; фактический интервал задаётся также в настройках HAPP.

## Публичный или приватный репозиторий

Для обычной Raw-ссылки в HAPP репозиторий должен быть публичным. Приватный Raw
требует авторизации GitHub, которую HAPP в поле подписки не передаёт. Поэтому в
репозиторий нельзя добавлять личные, платные или самостоятельно созданные
ключи.

## Ограничения безопасности

- Структурная проверка, рейтинг и стабильность не устанавливают личность и
  добросовестность владельца сервера.
- Владелец активного узла видит ваш реальный IP, время и объём соединений, а
  также адреса назначений. HTTPS защищает содержимое только при действительном
  сертификате.
- Публичные узлы не следует использовать для банка, криптокошельков,
  Госуслуг, рабочих административных систем и смены важных паролей.
- Не принимайте предупреждения о сертификатах и не устанавливайте сертификаты
  или приложения, предложенные владельцем узла.

Если источник недоступен, unit-тесты не проходят или осталось слишком мало
записей, workflow завершится ошибкой и не опубликует изменения.
